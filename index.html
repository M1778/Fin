Introduction to Fin

Fin is a modern, high-performance systems programming language designed around three core pillars: memory management as an explicit library, the sample corpus as the normative specification, and strict refusal invariants in backend code generation.

Unlike languages that hide runtime garbage collectors behind magical runtimes or mandate complex borrow-checker lifecycles into the compiler core, Fin treats memory models as modular libraries (ADR 0003). The compiler frontend focuses on rigorous semantic analysis, structural typing with prototypes, and compile-time event handlers, while the LLVM backend enforces strict safety guarantees without silently guessing intermediate representations.

The Non-Negotiable Backend Invariant

If code generation cannot lower a construct, it reports an explicit refusal. The Fin compiler will never silently drop runtime code or emit guessed LLVM IR. Every refusal explicitly names the construct and the ruling or architectural gap that governs it.

Core Philosophy #

  • No Prose Specification: The language specification lives as code in tests/samples/*.fin (ADR 0008). Each sample carries an explicit //@ expectation (ok, error, or unimplemented) that tests and convicts the compiler.
  • Single Unified Error Construct: blame replaces assert, panic, and throw. blame condition; asserts conditions, blame Error(...); raises error values, and blame m1778; marks unimplemented paths.
  • First-Class Structural Prototypes: {K,V} serves as an inference-first structural map type that converts cleanly to nominal containers like HashMap and Collection.
  • Two-Moment Layout Engine: Struct layout cleanly separates the decide phase (where header words and alignments are requested) from the observe phase (where byte sizes and typed pointer maps are queried).

Quickstart Guide #

The finc compiler operates in two primary modes: Analysis Mode (type-checking only) and Compilation Mode (emitting object files or linking native binaries).

finc -S program.fin

Hello, World! #

Create a file named hello.fin. In Fin, the entry point is a top-level function named main with a return type of <noret> (meaning returns no value):

fin 
//@ bundled
// Declare C's standard printf using @define
@define printf(fmt: string, ...) <noret>;

fun main() <noret> {
    printf("Hello, World from the Fin Systems Language!\n");
}

Compile and run the program:

bash 
$ build/finc hello.fin -o hello
Build Successful.
$ ./hello
Hello, World from the Fin Systems Language!
Return Types in Angle Brackets

In Fin, function return types are written after the parameter list inside angle brackets: fun name(...) <Type>. <noret> and <void> both represent functions that return no value.

Nullable Types (T?) & Denullify (expr?) #

Fin provides native nullability without unmanaged NULL pointer exceptions. Per ADR 0040, nullable value types (like int? or struct?) are lowered as deterministic tagged aggregates { T, bool } with a presence discriminant.

fin 
fun find_user_id(name: string) <int?> {
    if (name == "admin") {
        return 1; // implicitly wrapped into { 1, true }
    }
    return null;  // wrapped into { 0, false }
}

fun run() <noret> {
    let result <int?> = find_user_id("admin");

    if (result != null) {
        // Denullify operator (?) safely extracts the inner value
        let id <int> = result?;
        printf("User ID: %d\n", id);
    }
}

Control Flow #

Fin features structured control flow: if / else if / else, three-clause for loops, while, do / while, and a unique ternary syntax.

Ternary Conditional Expression (ADR 0005) #

Per ADR 0005, Fin's ternary operator is written: condition : then ? otherwise (colon precedes the true branch, question mark precedes the fallback):

fin 
let score <int> = 85;
// Condition : TrueArm ? FalseArm
let status <string> = score >= 50 : "Pass" ? "Fail";

    let count <int> = 3;

Structs & Methods #

A struct is a nominal aggregate type. Methods define their receiver explicitly using self: &Self. Sections of members and methods are scoped by pub: and priv: visibility labels.

fin 
pub struct Vector2D {
    priv:
        x <float>,
        y <float>,

    pub:
        // Constructor
        Vector2D(x: float, y: float) {
            self.x = x;
            self.y = y;
        }

        // Member method
        fun length(self: &Self) <float> {
            return math_sqrt(cast<double>(self.x * self.x + self.y * self.y));
        }

        // Operator overloading
        operator +(other: Vector2D) <Vector2D> {
            return Vector2D(self.x + other.x, self.y + other.y);
        }

        // Static factory method
        static fun zero() <Vector2D> {
            return Vector2D(0.0, 0.0);
        }
}

Interfaces & Generics #

Interfaces declare method signatures that types can implement nominally or via external implements blocks.

fin 
pub interface Drawable {
    pub fun draw() <noret>;
}

// Nominal implementation on a struct
pub struct Circle : <Drawable> {
    radius <float>,

    pub fun draw(self: &Self) <noret> {
        printf("Drawing circle of radius %f\n", self.radius);
    }
}

// Generic function bounded by an interface
pub fun render<T: Drawable>(item: T) <noret> {
    item.draw();
}
Constraint Sets vs. Storage Types (ADR 0018)

Constraint sets (such as type Number = int | uint | float;) are bounds for generic parameters and never concrete storage types. You cannot declare a field or variable of type Number directly.

Enums & Tagged Unions #

Fin enums encompass both simple C-style enumerations and rich tagged unions with member payloads (ADR 0041).

Pointers & Memory (rptr, wptr) #

Fin rejects language-mandated monolithic garbage collection. As defined in ADR 0003, memory management is implemented as a library. For automatic reference management, Fin standard library provides rptr<T> (sound reference-counted pointer with borrow tracking) and wptr<T> (weak non-owning observer).

fin 
import { rptr, wptr } from stdptr::std;

fun memory_lifecycle() <noret> {
    // 1. Allocate raw heap memory
    let buf <[int]> = new [int, 16]{};
    delete buf;

    // 2. Safe shared reference counting with rptr
    let ptr <rptr<int>> = rptr(42);
    printf("Refs: %d, Borrows: %d\n", ptr.refs(), ptr.borrows()); // 1, 0

    // Clone shared handle
    let handle2 <rptr<int>> = ptr.alias();
    printf("Refs after alias: %d\n", ptr.refs()); // 2

    // Exclusive borrowing
    let borrowed <rptr<int>> = ptr.borrow();
    borrowed.set(100);
    borrowed.giveback();

    // Release drops reference and frees memory at 0
    handle2.release();
    ptr.release();
}

Three Pillars of Fin's Memory Architecture

🎯 rptr<T> (Shared Borrow)

Sound reference-counted pointer. Manages runtime ref-count and active borrow tracking. When borrow is granted via .borrow(), mutation is strictly sequenced until .giveback().

👁️ wptr<T> (Weak Observer)

Weak non-owning observer handle. Monitors allocation lifetime without incrementing strong reference counts, preventing circular reference memory leaks.

⚡ @Alloc(Arena) (Custom Arenas)

User-defined custom memory managers. High-throughput linear bump allocators and pool allocators with deterministic batch release via defer arena.release().

Blame Error Handling #

Fin has no separate assert, panic, or throw keywords. Instead, it provides a single, cohesive mechanism: blame.

fin 
import { Error } from error::std;

fun divide(numerator: int, denominator: int) <int> {
    // 1. Assertion form: condition check with optional diagnostic message
    blame denominator != 0, "division by zero is forbidden";

    // 2. Raise form: raises an Error instance
    if (numerator < 0) {
        blame Error("negative numerators not supported in this domain");
    }

    return numerator / denominator;
}

fun incomplete_feature() <noret> {
    // 3. Unimplemented expression: eliminated as dead code or halts
    blame m1778;
}

Prototypes {K,V} #

Prototypes are built-in structural map types written as {K,V}. Two prototypes with the same key and value types are identical types. They convert explicitly into nominal library maps like HashMap (ADR 0028).

fin 
import { HashMap } from hashmap::std;

fun demo_prototype() <noret> {
    // Structural literal value
    let p <{string, int}> = { "port": 8080, "threads": 4 };

    // Explicit conversion into nominal O(1) HashMap
    let map <&HashMap<string, int>> = HashMap::from_prototype(p);
    printf("Port: %d\n", map["port"]);
}

Macros & Specials #

Fin distinguishes syntax macros from compiler extensions:

  • @macro: Operates on typed ASTs and returns a quote { ... } block (ADR 0023). Invoked with !.
  • @special: Compile-time execution functions running within the compiler. The only location where compiler components can be reached via #[use(...)] grants.
fin 
// AST-substituting macro
@macro magic_multiply(a, b) {
    return quote { $a * $b; };
}

fun calculate() <int> {
    // Invocation with exclamation point
    return magic_multiply!(10, 5); // Expands to 10 * 5
}

std::strings — String Manipulation #

    free_str(combined);
    free_str(trimmed);
    free_str(upper);

        printf("Resource is still alive!\n");
    }
    owner.release();
}
Standard Library

std::networking — Socket Facilities & Status #

The networking module status is specified under ADR 0008. The module boundary is bundled in lib/std/networking.fin to allow module imports. Low-level POSIX socket externs (socket, bind, listen, accept, connect, send, recv) are bridged to the libc socket layer.

Network Sockets Roadmap

Programs requiring network communication currently interface with standard POSIX socket bindings via @define extern declarations matching the C runtime ABI.

The Fin Compiler Pipeline Flow #

From high-level source text to optimized machine code. Every stage guarantees type soundness, explicit memory layout, and deterministic refusal invariants.

01 SOURCE Source (.fin) tests/samples/*.fin
02 PARSER Lexer & Parser Flex / Bison LALR(1)
03 AST AST Cloning Structural AST
04 SEMANTICS Semantic Analyzer Two-Moment Layout
05 CODEGEN LLVM Lowering Refusal Invariants
06 EMIT Machine Code x86_64 / AArch64 / WASM

⭐ Key Architectural Guarantee: Strict Backend Refusal Invariant

If the LLVM code generator encounters an unhandled construct or cannot prove layout invariants, it reports an explicit refusal. The Fin compiler will NEVER silently guess intermediate representations, drop code paths, or emit unsound LLVM IR.

Architecture Invariants & ADRs #

Fin has no prose specification. Per ADR 0008, tests/samples/*.fin serves as the single source of truth. Every Architectural Decision Record (ADR) in docs/adr/ defines an immutable structural invariant:

ADR Title & Invariant
0001m1778 means "not implemented". Reaching it is compile-time or run-time failure.
0002Fresh LLVM backend. AST lowering produces direct LLVM IR without intermediate C emission.
0003Memory management is a library, not built-in compiler magic.
0005Ternary is written condition : then ? otherwise.
0008Sample authority is per-expectation (//@ ok, //@ error, //@ unimplemented).
0011A bare brace opens an explicit lexical scope.
0018A constraint set is a bound, never a storage type.
0019An interface reference is two words: data pointer and vtable pointer.
0036Struct equality (==) is declared-only, never synthesized automatically.
0040Nullable values are tagged aggregates { T, bool }; nullable pointers use null sentinel.
0041Enums are tagged unions with 32-bit discriminants and byte-aligned payload buffers.
0042Compiler API builtins (@implements, @defined, @Alloc, @Free) map to unified compiler components.
Compiler Architecture

Compiler Refusal Invariants #

A foundational guarantee of the finc compiler backend:

Refusal Rule

Whenever the code generator encounters a type, operator, or expression that cannot be fully lowered to LLVM IR, it halts with an explicit refusal diagnostic: codegen: <construct> is not lowered yet. It will NEVER silently omit execution code or substitute stub IR.

Compiler Architecture

Backend LLVM Lowering #

The backend maps high-level Fin AST constructs directly into optimized LLVM IR representations:

  • Nullable Values (ADR 0040): Value types lower as an LLVM struct { T, i1 }. Pointers lower as raw 64-bit pointers with NULL checks.
  • Enums & Tagged Unions (ADR 0041): Fieldless enums map to i32. Payloaded enums map to { i32, [MaxPayloadSize x i8] }, ensuring standard C ABI calling compatibility.
  • Dynamic Arrays (ADR 0025): [T] is exactly two words: a 64-bit pointer to heap elements and a 32-bit/64-bit length.
  • Interface References (ADR 0019, 0027): Two words: data pointer and vtable pointer. The vtable carries function pointers alongside embedded field offsets.
