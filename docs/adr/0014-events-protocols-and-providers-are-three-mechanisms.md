# Events, protocols and providers are three mechanisms, told apart by what the library may produce

A library extends the compiler through exactly one of three mechanisms, and which one it needs is
decided by what it produces rather than by what it is about.

An **event** injects code at a program point the compiler chose. Many libraries may subscribe to one
event, none of them exclusively, and none can see or invalidate another's contribution (ADR 0007).
Declared `#[on(<event>)]`, armed by a call.

A **protocol** replaces one compiler operation. Exactly one library may claim a slot, and the claimant
answers for the whole operation rather than adding to it. Declared `#[protocol(<slot>)]`. The slots are
`move_or_copy`, `deallocate`, `lifetime` (for `#[slaveof]`, `variables.fin:21-34`) and `destructor`.

A **provider** answers a question the compiler asks. The compiler calls it once per subject, stores the
returned value, and emits it. Declared `#[provides(<slot>)]`; the motivating slot is a type's pointer
map. Exclusive per slot, memoised per subject.

## Why three, when one would do

Each is a different write power, and ADR 0007's read-broadly-write-narrowly asymmetry only means
something if the write channel is named. An event writes at a point it did not choose. A protocol writes
a replacement for a node the compiler handed it. A provider writes nothing at all — it returns a value,
and the compiler does the writing. Collapsing them yields one mechanism holding the union of all three
write powers, which is precisely what ADR 0007 refused.

The corpus asks for the distinction rather than tolerating it. `deeptest2.fin:46` says "basic destructors
are generated by compiler by default but you can overwrite it" — overwrite, not add to, which no event
can express. And `#[slaveof]` is a lifetime relation the compiler must implement on the library's behalf,
not a point at which to inject.

No language names all three, but each exists in isolation somewhere: D's `object.RTInfo` is a provider
and D ships a working precise collector on it; Nim's `=copy` and `=destroy` are protocols; Rust's
procedural macros are events with the write restriction removed. The value of naming all three together
is that a library author asking "which do I want" gets three answers instead of one hole.

## Consequences

The question ADR 0007 delegated — is the per-type pointer map an event or a query — is answered here as
neither. It is a provider. A query would need a "list all types" operation and a loop over it, and
ADR 0006's line has no loop; an event would need mutable compile-time state across invocations and a
write channel outside the event point, which ADR 0007 forbids.

Exclusivity now exists. ADR 0007 recorded its absence as a limitation, and two claimants on one protocol
or provider slot is a diagnostic naming both. What it does not do is make event handlers exclusive: two
collectors may still both arm `variable_scope_exit` and both free the same variable, exactly as ADR 0007
says. The language now has a place to mean "one of these" and a place to mean "all of these", and which
one a given extension point gets is a decision per slot rather than an accident of mechanism.

A provider must be a pure function of its subject. The compiler is entitled to call it once and reuse the
answer, and entitled not to call it at all when nothing observes the answer. A provider written for its
side effects is a bug that the compiler will not catch and should not be expected to.

Eight of the nine jobs in the motivating collector (ADR 0003, `CortexGC.fin`) now need no amendment to
any existing decision. The ninth is the safepoint, which is ADR 0007's `loop_back_edge`.
